2. Understand a recipe

SW_KATANA_NATURE_T3 means a Katana, Nature path, visual stage 3. An ID is a stable lookup key. Store it in saves and resolve the current sprite/texture through assets.json.

  • upgrade: T1 → T2 → T3 → T4 → T5 within one path and archetype.
  • elemental_transform: Neutral T3 → an elemental T1 of the same archetype.
  • fusion: one T3 item from each listed parent element → fusion T1 of the same archetype.
Tiers describe a visual stage within a path. They are separate from your game's rarity, attack damage, item level, drop probability or cost. A fusion T1 can be stronger than an elemental T3 in your game; the artwork does not assign that balance.

Canonical fusion

{
  "recipe_id": "FUSE_LONGSWORD_ROOTSTONE",
  "kind": "fusion",
  "archetype_id": "LONGSWORD",
  "inputs": [
    {
      "item_id": "SW_LONGSWORD_NATURE_T3",
      "quantity": 1
    },
    {
      "item_id": "SW_LONGSWORD_EARTH_T3",
      "quantity": 1
    }
  ],
  "output_item_id": "SW_LONGSWORD_ROOTSTONE_T1",
  "output_quantity": 1,
  "resource_costs": [],
  "requirements": []
}

Consume the two ingredient items only after all required quantities, resources and requirements have been validated. Then grant the output. If validation fails, change nothing. Repeat the output path's four upgrade recipes to reach T5.

Read CSV correctly

Use a CSV parser. Do not split lines on commas: the recipe CSV contains quoted JSON arrays with commas inside cells. Parse inputs_json, resource_costs_json and requirements_json as JSON after reading each CSV row. The JSON and CSV tables contain matching recipe IDs.

3. Unity integration

  1. Import the native Unity package or configure the PNGs as sprites. The native sprite location is Assets/SwordsEvolutionFusion1000/Icons/{ARCHETYPE}/{ID}.png.
  2. Open SwordCatalogExample.cs.txt. Copy it to your code folder as SwordCatalogExample.cs when you want to use the example. Example source stays in .txt form so importing this artwork cannot accidentally compile code into your project.
  3. Attach the component to a GameObject. Assign assets.json and recipes.json as TextAssets, the desired sprites as a Sprite[], and a SpriteRenderer. This example uses built-in Unity types without adding a UGUI dependency. To display its output in an inventory UI, assign the resolved Sprite to your own UI Image; Unity UI requires com.unity.ugui in your project.
  4. The reader uses JsonUtility and serializable arrays/public fields. It creates dictionaries after deserialization, keyed by IDs. Sprite names must equal the item ID; the native package follows that convention.
  5. The sample creates an inventory containing Nature T3 and Earth T3 longswords, applies FUSE_LONGSWORD_ROOTSTONE, and displays the output if its sprite is registered. Replace the sample dictionaries with your own inventory model.

SwordCatalogEditorLookup.cs.txt shows Editor-only lookup by unity_asset_path. Put copied Editor code in an Editor folder. AssetDatabase is not a runtime loading API. For a built game use assigned Sprite references, your own Addressables setup, or a lookup prepared during your build. Renaming or relocating native files requires updating the corresponding manifest paths.

Verified in actual Unity 6000.5.4f1: these exact source examples compiled, parsed all 1,000 asset records and 990 recipes, and applied all 990 recipes successfully. 4. Unreal integration

Blueprint-friendly CSV route

Follow Blueprint_Integration.txt. Create the specified Blueprint Structures, import the two Metadata/Unreal CSVs as DataTables, and query recipe rows by ID. Validate both ingredient quantities, change your inventory, then query the output asset row to retrieve its texture path.

The texture path is /Game/SwordsEvolutionFusion1000/Icons/{ARCHETYPE}/{ID}.{ID}. Convert the path to a soft object reference and load the Texture2D for your UMG Image. Your project supplies the inventory and UMG widget.

C++ JSON route

Header example and source example read assets.json into a TMap and resolve Texture2D objects by the exact unreal_object_path. Copy and rename the files into your own C++ module, then add the documented Json/JsonUtilities module dependencies. The artwork project remains content-only.

Test an actual packaged build

External path strings do not themselves guarantee that textures are included in a cook. Register the icon directory with your Asset Manager/Primary Asset Labels or appropriate cook settings. Stage metadata files if loading JSON/CSV from disk at runtime. The sample accepts an absolute JSON filename, so you choose a valid packaged location. Keep a referenced loaded texture alive while it is in use. Native project previews and these examples do not replace a packaged-build check for your game.

6. Adapt the data to your game

Default recipes set both resource_costs and requirements to empty arrays. This makes the proposed relationships usable without imposing an economy. customized_cost_example.json demonstrates adding an external forge resource and a minimum player level; it is excluded from the 990 canonical recipes, and its resource is not supplied artwork.

Use your own combat stats, rarity labels, prices, prerequisites, unlocked recipes and save behavior. Preserve item IDs if you want saves and recipe references to remain compatible. If you remove or rename an item, update every incoming/outgoing recipe and regenerate its maps. Revalidate schema, referenced IDs, ingredient quantities, duplicate IDs and graph cycles after editing.

Included: static artwork, portable data, illustrative recipes, evolution maps, integration source examples and documentation. A working inventory, combat loop, crafting UI, multiplayer authority, save system and balanced economy are implementation work in your game.
